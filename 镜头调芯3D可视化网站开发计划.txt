镜头调芯 3D 可视化网站 —— 可行性方案与 AI 编程成本预估
====================================================================

一、背景与目标
--------------------------------------------------------------------
参考网站: https://anvcor.github.io/lens-bench (镜头 MTF 仿真台)
  技术栈: 纯前端零依赖单页应用(vanilla JS + 内联 SVG 渲染 + 本地实光线追迹内核,
          无构建、无后端, standalone.html 单文件双击即跑)
  核心能力: LDM 表格直接编辑 / 2D Layout / MTF vs 视场 / 球差·场曲·畸变 /
            Ray Fan / 双镜头对比 / .zmx 与 .seq 导入 / 19 家 3074 种玻璃库

本项目目标:
  1. 构建功能类似的光学仿真网站(以 lens-bench 为规格参考、代码全部重写——其仓库无
     LICENSE, 默认保留所有权利, 直接复制代码有法律风险; 算法/公式属公开理论不受限)
  2. 本地部署运行
  3. 在网站上对镜头做 3D 可视化, 每个镜片的坐标位置可调
  4. 坐标可调语义: 轴向(Z) + 偏心(X/Y) + 倾斜, 且偏心/倾斜真实参与光线追迹(6 自由度)

技术风险等级: 高 —— 这意味着要把参考站的"共轴追迹内核"升级为"通用坐标架非共轴内核",
              属于光学软件工作量最大的一档。结论: 可行, 但必须分阶段推进,
              每一阶段都先部署可运行、可验收, 不要一口气做完。


二、总体架构与技术选型
--------------------------------------------------------------------
本地浏览器(无后端, 同参考站理念)

  ├─ 引擎层  全局坐标实光线追迹(球面/圆锥/偶次非球面, 每面带 decenter X/Y
  │          + tilt 绕 X/Y/Z)
  │          通用面坐标架: 光线变换到面局部系→解二次方程求交→矢高/斜率局部求
  │                        →变换回全局坐标
  │          偏心系统的光学量约定: EFL/F#/光瞳按"参考轴"定义
  │          (近似 CODE V 的参考光线策略)
  │
  ├─ 数据层  面表记录扩展(THI / DEC X·Y / TILT, element 镜片分组, 结构配置)
  │          支持撤销/重做/剪贴板粘贴
  │
  ├─ 解析层  .zmx / .seq 导入(读取偏心倾斜字段: Zemax 的 YDE/XDE/ADE/BDE,
  │          CODE V 的 YDE/XDE/ADE/BDEx; 渐晕系数 SETVIG / VDYN·VCYN;
  │          多重结构 MNUM/THIC/APER/FVCY 与 ZOO)
  │
  ├─ 计算层  光阑定义 / 光线瞄准(牛顿迭代瞄到光阑面) / 渐晕(SETVIG 式二分) /
  │          衍射 MTF 与几何 MTF / 球差·场曲·畸变 / Ray Fan / 最佳对焦
  │
  ├─ 可视化  2D Layout 用 SVG 重写; 3D 用 Three.js
  │          镜片实体(Lathe/扫描体)+玻璃材质+3D 光线+半剖切面
  │          + 轴向与 6-DOF 拖拽手柄 + 数值编辑面板, 与表格/2D 双向实时同步
  │
  └─ 玻璃库  先支持 nd/vd 写法 + 6 位 MIL 代码 + 3~5 家少量常用牌号
             (完整 19 家 3074 种数据采集另计, 见风险与降本策略)


三、本地部署方式(M0, 第一天就能做)
--------------------------------------------------------------------
  1. 先把参考站静态镜像到本地: 进入静态目录后执行
       python -m http.server 8000
     浏览器打开 http://localhost:8000
  2. 本项目的开发期用 Vite dev server(带 Three.js 依赖、热更新):
       npm create vite@latest && npm i three
       npm run dev
  3. 最终产物仍是纯静态(可整目录拷贝/拖到内网), 与参考站理念一致。

       3D 六自由度拖拽 + 数值输入; 2D 投影按偏轴后实际光路绘制。
       验收: 偏心/倾斜结构的 2D/3D 光路、Ray Fan、点列、最佳对焦可正确计算;
             用 Zemax 偏心示例文件(坐标断点镜头)逐点比对验证。

  M5  双镜头对比页 / 关于页 / 性能优化 / 发布(15%)
       对比模式共用光谱·频率·算法(同参考站约定)、完善帮助文档、运行性能优化。

  玻璃库完整数据(3074 种牌号)不建议用 LLM 生成——容易出错且本质是"数据采集/转录"
  而非代码任务, 建议单列人工子任务并后置。


五、偏心/倾斜系统(6-DOF)的关键技术点
--------------------------------------------------------------------
  1. 面坐标架与全局追迹:
     每面在全局坐标下定义局部坐标系(平移到顶点+旋转), 光线经逆变换到局部系,
     在局部系解二次曲面求交、算矢高与法线, 再变换回全局。共轴只是特例(全零)。
  2. 光学量的参考轴定义:
     系统整体偏心/倾斜后, EFL、F#、入瞳等近轴量失去唯一的全局意义。
     采用"参考轴"(由设计意图定义, 近似 CODE V 参考光线做法)作为度量基准,
     这是难点, 需与光学工程师确认约定后实现。
  3. 衍射 MTF 的瞳孔处理:
     偏心大视场上光瞳建模与取样极其敏感, 建议推迟到最后一小步, 并只按参考轴验证;
     先做到"实光线正确穿过偏轴元件 + Ray Fan/点列/最佳对焦可算"。
  4. 渐变验证路径:
     共轴全通过后再开小偏心(0.1mm/0.1°)逐步加大, 每个量级与 Zemax 对照。

  强烈建议顺序: M2/M3(共轴全功能+3D) → M4(偏心/倾斜), 中间产物本身就有价值。


六、AI 编程成本预估(国产 API 按量, 人民币)
--------------------------------------------------------------------
参考站源码规模(已实测分析):
  optics.js 追迹内核 ≈ 79KB; app.js 界面 ≈ 93KB; glassdb.js ≈ 220KB;
  index.html ≈ 52KB; standalone.html(单文件版)≈ 858KB。

DeepSeek 官方单价(2026-09 查询, 人民币/百万 tokens, 汇率≈7.1;
  谷时为峰时一半, 缓存命中另有大幅折扣, 以官网当日为准):
  模型                    输入(未命中)      输出
  deepseek-v4-flash       ¥1.6 ~ 3.1        ¥4.7 ~ 9.4
  deepseek-v4-pro         ¥4.7 ~ 9.4        ¥14 ~ 28

Token 消耗结构说明:
  - AI 编码代理需要反复读改大文件、工具输出与验证返工, 输入 token 通常约为输出的
    10 倍左右;
  - 开启 thinking(思考)模式时输出会被放大数倍并同样计费;
  - 因此本表只给"总输入 / 总输出"口径, 便于你自己按上述单价换算。

预算场景估算(纯 API 费):
  场景                              输入量        输出量      纯 API 费估算
  全程 flash、顺利                    ~30M        ~3M        ≈ ¥50 ~ 150
  全程 flash、含返工(典型)            ~60M        ~6M        ≈ ¥100 ~ 250
  flash 为主、核心数值段用 pro        ~60M        ~6M        ≈ ¥300 ~ 700
  悲观(重大返工 2~3 轮)             ~120M       ~12M        flash≈¥600 / pro≈¥1700

!重要: 真实成本大头不是 token, 而是人工盯守与验收的人时。
  这类数值软件的正确性要靠反复比对(参考站/Zemax 数值、跑回归)。
  按上述节奏估算: 需 1 名光学工程师专职 8~14 人周(自然月约 1.5~3 个月),
  API 费用只占其中很小一部分。


七、省钱 / 降风险的关键决策
--------------------------------------------------------------------
  1. 先共轴后偏轴: M2/M3 完成后再动 M4, 每个中间产物独立可用、可验收。
  2. 偏心系统的衍射 MTF 推迟: 偏心大视场上衍射 MTF 极敏感, 放最后且只做参考轴验证。
  3. 玻璃库最小化起步: 先支持 nd/vd、MIL 码与 3~5 家牌号, 够跑参考站库里镜头即可。
  4. 用参考站当验收基准: 数值对比结果不属版权内容, M2 阶段可直接逐点对它的 MTF;
     偏心阶段用 Zemax 坐标断点示例比对。
  5. 模型混合策略: 脚手架/UI/表格用 flash(便宜量大); M2 的 MTF 算法与 M4 的
     非共轴数学用 pro 攻坚, 减少返工轮次, 省下的主要是人时。
  6. 玻璃库完整数据(19 家 3074 种)单列人工子任务, 从公开厂商目录(各官网 Excel/PDF)
     采集, 不要在代码阶段并行推进。


八、风险清单
--------------------------------------------------------------------
  1. 非共轴内核 + 衍射 MTF 组合是最大风险点 → 分 M4 并逐步验证(第五节第 4 条)。
  2. .zmx 版本差异与偏心字段解析 → 用参考站库内真实文件 + 自备 Zemax 文件双轨测。
  3. 3D 拖拽与数值追迹的性能 → Web Worker 跑追迹, 拖拽节流, Three.js 分批渲染。
  4. 玻璃数据版权/转录错误 → 用厂商官方目录, LLM 只写采集脚本, 逐牌号抽检。
  5. 验收基准偏差 → 提前固定一组"黄金用例"(含偏心结构), 每阶段回归。

十、技术路线总结记录(决策台账)
====================================================================
  10.1 总原则
    · 参考站(lens-bench)仅作【规格参照】与【数值验收基准】; 其仓库无 LICENSE,
      代码不复制、不进入本项目仓库与发布产物; 启动台不再展示其本地镜像(改挂本记录)。
    · 算法/公式属公开理论: 可阅读理解后自行重写, 逐点对齐数值即可。
    · 引擎全部自研, 保持【单一追迹栈】(避免双引擎/双玻璃库导致同一镜头两处读数不一致)。

  10.2 引擎现状(自有)
    · trace.js: 3D(x,y,z) 旋转对称实光线追迹; 球/圆锥/偶次非球面; 折射率用
      2026 玻璃库 Sellmeier(glassdb.js)。
    · 已具备: 一阶量(EFL/BFL/F#)、视场光束与主光线瞄准、入瞳、自动渐晕(逐面半孔径)、
      点列图、相对照度(一维)。
    · 尚缺(MTF 所需): 光程 OPL 累加、参考球 OPD、离焦面平移、PSF/OTF/MTF。

  10.3 MTF(含离焦)路线决策 —— 采纳【路线 B(自研重写)】
    · 路线 A(直接复用 reference/js/optics.js): 短期便宜(≈3~5 人日), 但引入双引擎/双玻璃库,
      结果与自有 2D/3D/点列/相对照度不一致; 且该内核为共轴旋转对称, 不支持 6-DOF,
      与 M4 目标冲突; 另有许可风险。→ 不采纳。
    · 路线 B: 在自有 traceRay3 上扩展:
        ① 逐段累加 OPL = Σ n·L;
        ② 以像点主光线为参考球心算 OPD(逐波长扣活塞项);
        ③ 离焦 = 像面/参考球沿轴平移 Δz, 加 W20 相位;
        ④ 瞳函数 P = A·exp(i2πW/λ) → 2D FFT → PSF → OTF → MTF = |OTF|;
        ⑤ 多色按权重对复 OTF 求和。
      成本 ≈ 5~13 人日; 结果与自有引擎一致; traceRay3 已是 3D, 可平滑服务 M4 的 6-DOF。
    · 分阶段:
        P0  轴上·单色·离焦闭环(≈2 人日)。验收: 无像差时精确等于圆孔衍射极限
            MTF = 2/π·(acos s − s·√(1−s²)); 已知 W20 离焦与理论一致。
        P1  多视场 + T/S 分离 + 曲线图(≈2 人日)。
        P2  多色复 OTF + 有效瞳(渐晕) + 像方方向余弦截止频率(≈3~5 人日)。
    · 直接照抄 optics.js 仅可作为【本地一次性对照工具】(不进仓库), 用于标定自研实现。
    · 备注: 相对照度已先行落地(v0.7.6, 一维), 其瞳采样与 OPD 网格可被 M2c 复用。

  10.4 分阶段验收基准
    · 共轴: 与参考站数值逐点对齐(MTF 差 ≤ 0.01 为 M2c 验收线)。
    · 偏轴: 用 Zemax 坐标断点示例比对。
    · 每阶段固定一组"黄金用例"做回归。
